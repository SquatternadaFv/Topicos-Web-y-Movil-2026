Lenguajes de programación y sus patrones de diseño

Frontend Web (Interfaces de Usuario)
React (Flujo Unidireccional / Arquitectura Flux): A diferencia del enlace de datos bidireccional (two-way binding), React fuerza a que los datos fluyan en una sola dirección: de un componente padre a un hijo mediante props. Cuando ocurre un evento (como un clic), el hijo emite una acción hacia arriba, el estado se actualiza en la cima, y React vuelve a renderizar el árbol hacia abajo. Esto hace que el estado de interfaces complejas sea predecible y fácil de rastrear (especialmente con herramientas como Redux).
Angular (Inyección de Dependencias y Observer): Angular obliga a pensar en servicios aislados. En lugar de que un componente cree sus propias herramientas (ej. un servicio HTTP), el framework se las "inyecta" (IoC) cuando el componente nace, facilitando enormemente las pruebas unitarias. Además, maneja casi toda su asincronía (eventos, peticiones HTTP, formularios) a través de Observables (RxJS), lo que permite cancelar, filtrar y combinar flujos de datos en tiempo real.
Vue.js (MVVM - Model-View-ViewModel): Vue encapsula la complejidad de actualizar el DOM. Tú solo te preocupas por el Modelo (tus datos en JavaScript). La instancia de Vue actúa como el ViewModel: crea "proxies" reactivos alrededor de tus datos, los vigila, y cuando detecta un cambio, actualiza automáticamente la Vista (el HTML) de forma quirúrgica.

Backend Web Tradicional (MVC y derivados)
Laravel - PHP (MVC y Active Record): MVC separa la lógica: el Router recibe la petición y llama al Controlador; este procesa la lógica de negocio apoyándose en el Modelo (Eloquent) y devuelve una Vista (Blade). El patrón Active Record hace que cada clase del Modelo represente una tabla de la base de datos, y cada instancia de esa clase represente una fila, dándole al propio objeto la capacidad de guardarse o borrarse a sí mismo ($usuario->save()).
Ruby on Rails (MVC y Active Record): Es el framework que popularizó esta estructura. Su filosofía central es "Convención sobre Configuración": si nombras tus tablas y clases siguiendo las reglas de Rails, el framework infiere las relaciones y configuraciones automáticamente usando Active Record, eliminando la necesidad de escribir código repetitivo y conectando el Controlador con la Vista de forma casi mágica.
Django - Python (MVT - Model-View-Template): Funciona igual que el MVC, pero cambia los nombres. En Django, lo que normalmente llamamos "Controlador" se llama "Vista" (View), ya que es el código que "ve" qué hacer con la petición. Y lo que normalmente llamamos "Vista" (el HTML) se llama "Plantilla" (Template). Su Modelo utiliza un ORM propio que también usa el patrón Active Record.

Backend Moderno y API (Microservicios e IoC)
Spring Boot - Java (Inversión de Control / IoC): En un sistema Java empresarial, gestionar dependencias manuales crea un código sumamente acoplado. Spring resuelve esto con su contenedor IoC. Tú simplemente anotas una clase con @Service y otra con @Autowired, y el framework toma el control absoluto: crea las instancias, gestiona su ciclo de vida y las conecta entre sí al arrancar la aplicación.
NestJS - Node.js (Patrón Decorador): Inspirado fuertemente en Angular y Spring, usa decoradores (como @Get(), @Post(), @Injectable()) para añadir metadatos a las clases de TypeScript sin alterar su lógica interna. Esto permite transformar una clase normal en un controlador de API o en un servicio inyectable de manera declarativa y limpia.
Node.js con Express (Cadena de Responsabilidad / Middleware): Cada petición HTTP pasa por un túnel. Un middleware es una función en ese túnel que toma la petición, hace algo (ej. verificar si el usuario está autenticado, registrar logs) y decide si responde inmediatamente o si llama a la función next() para pasarle el control al siguiente eslabón de la cadena.
Programación de Sistemas y Concurrencia
Go / Golang (Worker Pool y Fan-In/Fan-Out): Go fue diseñado para la concurrencia masiva. En lugar de crear hilos pesados del sistema operativo, usa goroutines (hilos ultraligeros) que se comunican mediante channels (canales). El patrón Worker Pool permite tener un número fijo de goroutines esperando tareas de un canal, limitando el consumo de recursos mientras se procesan miles de operaciones simultáneas de forma segura.
C++ (RAII - Resource Acquisition Is Initialization): C++ no tiene recolector de basura (garbage collector). Para evitar fugas de memoria, usa este idioma de diseño donde un recurso (memoria, apertura de un archivo, sockets) se adquiere en el constructor de un objeto y se libera siempre de forma automática en su destructor cuando el objeto sale de su ámbito (scope), garantizando seguridad y rendimiento extremo.
Rust (Patrón Builder y Máquina de Estados): Debido a las estrictas reglas de "propiedad" (ownership) del compilador de Rust para garantizar la seguridad de memoria, patrones mutables clásicos son difíciles de implementar. El Builder Pattern es la norma para construir estructuras complejas paso a paso antes de finalizarlas. Además, su potente sistema de Enums se usa para modelar Patrones de Estado (State), haciendo que los estados inválidos sean imposibles de compilar.
Java y C# / .NET (Singleton y Factory): Ambos lenguajes son los pilares de la Programación Orientada a Objetos. Utilizan Factories (Fábricas) para ocultar la lógica compleja de creación de objetos polimórficos, y Singletons para garantizar que servicios transversales (como una conexión a base de datos o un gestor de logs) tengan una única instancia viva en todo el sistema.


Desarrollo Móvil y Multisector
Swift para iOS (VIPER): El MVC clásico en Apple solía terminar en lo que la comunidad bromeaba como "Massive View Controller", archivos gigantes imposibles de mantener. VIPER (Vista, Interactor, Presentador, Entidad, Enrutador) rompe esto separando radicalmente las reglas de negocio (Interactor) de la navegación (Router) y la presentación.
Kotlin para Android (Clean Architecture): Promovido oficialmente por Google, separa la app en capas concéntricas. La Vista (UI) solo habla con el ViewModel, el ViewModel habla con Casos de Uso (Dominio), y estos hablan con el Repositorio (Datos). Esto garantiza que la lógica central no sepa absolutamente nada de Android, bases de datos o la red.
Flutter - Dart (BLoC - Business Logic Component): BLoC se basa completamente en Streams (flujos de datos reactivos). La interfaz de usuario envía eventos a un componente BLoC (ej. "Botón presionado"). El BLoC procesa la lógica y emite un nuevo estado a través de otro Stream. La UI simplemente escucha ese Stream y se redibuja, logrando una separación total entre la pantalla y la lógica.


Paradigma Funcional y Distribuido
Elixir y Erlang (Modelo de Actores): No hay objetos compartiendo memoria ni estados globales. Todo corre en "actores" (procesos ligeros aislados). Si un actor quiere que otro haga algo, le envía un mensaje a su buzón (mailbox). Este aislamiento absoluto permite el patrón "Let it crash" (déjalo fallar): si un proceso muere por un error, un proceso "Supervisor" lo reinicia instantáneamente sin afectar al resto del sistema.
Haskell (Mónadas y Functores): Al ser matemáticamente puro, en Haskell una función no puede tener efectos secundarios (como imprimir en consola o leer una base de datos). Para lograr que el lenguaje sea útil en el mundo real, envuelve los valores en estructuras llamadas Mónadas (ej. IO Monad). Esto permite encadenar operaciones secuenciales que sí tienen efectos, manteniendo la pureza del código principal.
Scala (Cake Pattern): Combina orientación a objetos y programación funcional. En lugar de usar frameworks pesados para la inyección de dependencias, Scala usa "mixins" (mezclando clases abstractas mediante Traits). Las dependencias se declaran y verifican estrictamente en tiempo de compilación, de modo que si falta una pieza, el código simplemente no compila, ofreciendo una seguridad que los contenedores IoC en tiempo de ejecución no pueden igualar.
