# Complemento posterior al diagnóstico

Se conserva el diagnóstico original como respuesta del 27 de agosto. Este complemento resuelve vacíos e imprecisiones posteriormente, con asistencia; no se presenta como una respuesta escrita aquel día.

1. Cascada organiza fases con mayor planificación previa y cambios que pueden exigir revisar entregables anteriores; Scrum trabaja por iteraciones e inspección/adaptación. Ninguno garantiza por sí solo calidad ni prohíbe que cambien requisitos.
2. Funcional: registrar un pedido y asignarle folio. No funcional: responder el 95 % de consultas de seguimiento en menos de un tiempo acordado y controlar acceso por permisos. Una elección visual también puede ser requisito de interfaz, no define por sí sola toda la categoría no funcional.
3. Cliente y servidor intercambian peticiones/respuestas por un protocolo, normalmente HTTPS y JSON; el servidor ejecuta reglas y controla persistencia. Puede renderizar HTML además de exponer API.
4. **SQL frente a NoSQL:** usaría una relacional para pedidos, pagos y relaciones con consistencia y transacciones. Una documental puede convenir para documentos de estructura variable y patrones de acceso que lo justifiquen. Tamaño o cambios no obligan a NoSQL; SQL también escala y existen bases NoSQL transaccionales. La decisión depende de consultas, consistencia, índices y operación.
5. REST organiza recursos y representaciones con interfaz uniforme; GET consulta, POST crea/procesa, PUT sustituye, PATCH modifica y DELETE elimina según contrato. No toda URL con JSON cumple REST. La API desacopla Flutter de la base y del modelo.
6. Git conserva versiones y permite integrar cambios. Un conflicto ocurre cuando Git no puede reconciliar automáticamente cambios incompatibles, por ejemplo editar las mismas líneas de formas distintas. Se inspeccionan ambas intenciones, se resuelve y se verifica el resultado.
7. **Pruebas unitarias:** comprueban una unidad de comportamiento de forma acotada y repetible; por ejemplo que un dron sea inviable a las 3:00. Detectan regresiones y ayudan a cambiar el código con confianza. No sustituyen pruebas de integración, contrato o una demostración del producto.
8. **Encapsulamiento** protege estado e invariantes detrás de operaciones del objeto; no consiste únicamente en añadir getters/setters. **Polimorfismo** permite invocar el mismo contrato en implementaciones distintas: medio.planear funciona para dron y moto. No exige que una clase se transforme en otra ni que siempre reduzca líneas.
9. **MVC:** Modelo representa estado/reglas, Vista presenta y Controlador interpreta entradas y coordina. En Django los nombres se reorganizan como MTV. Poner tres carpetas no garantiza separar responsabilidades: una plantilla que ejecuta SQL sigue mezclando datos y presentación.
10. Autenticación comprueba identidad. Autorización determina qué puede hacer esa identidad sobre un recurso. Estar autenticado no autoriza consultar el pedido de otra persona.
